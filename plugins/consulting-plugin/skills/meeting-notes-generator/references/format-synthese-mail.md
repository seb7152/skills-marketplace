# Format Synthèse Mail - Résumé pour Email

## Usage
Synthèses brèves et directes envoyées par email à une audience interne ou restreinte. Ton conversationnel mais professionnel, axé sur l'action et les informations critiques. Scannable en 2–3 minutes.

## Structure obligatoire

### Subject Line
```
Synthèse réunion : [Titre court] - [DD/MM]
```

### Corps du mail

#### 1. Intro (court)
```
Bonjour à tous,

Voici la synthèse de la réunion [Titre] du [DD/MM].
```

#### 2. Participants
Liste bullet simple avec rôles/contexte :
```
Participants:
- Prénom Nom (Rôle/Fonction)
- Prénom Nom (Rôle/Fonction)
- Prénom Nom (Rôle/Fonction)
```

#### 2. Objectif de la réunion
**IMPORTANT** : C'est le POURQUOI de cette réunion spécifique, pas le projet global. Répondre à : "Qu'est-ce qu'on cherchait à accomplir/clarifier/décider lors de cette réunion?" (2-3 lignes max).
Ne pas confondre avec l'objectif global du projet ou de la mission - celui-là serait une description plus large. Ici, être précis et ciblé sur ce qu'on visait ce jour-là.
```
Objectif:
[Pourquoi cette réunion? Qu'on cherchait à accomplir? (2-3 lignes)]
```

#### 3. Points clés
Structure avec 1-2 niveaux de bullets. Chaque bullet principal 2-3 lignes, sous-bullets pour détails. Utiliser ***gras italique*** ponctuellement pour mettre en avant des éléments critiques :

```
Points clés:
- ***Sujet important***: description générale 2-3 lignes avec mise en avant du point crucial.
  - Détail technique ou implication
  - Autre aspect ou conséquence
  
- Sujet standard: description générale 2-3 lignes sans mise en avant particulière.
  - Point de blocage: ***enjeu critique*** à arbitrer
  - Approche possible ou solution
```

Équilibre : 70% contenu informatif, 30% structure claire. Chaque point apporte une information. Utiliser ***gras italique*** uniquement pour éléments qui méritent vraiment la mise en avant (blocages, décisions clés, points critiques).

#### 4. Arbitrages (si applicable)
**FLEXIBLE** : Cette section s'adapte à ce qui a été discuté. Trois cas possibles :

**Cas 1 - Arbitrages à instruire** (questions ouvertes qui demandent une décision ultérieure) :
```
Arbitrages à instruire:
- [Sujet 1 : question ouverte avec enjeux]
- [Sujet 2 : question ouverte avec enjeux]
```

**Cas 2 - Décisions prises** (consensus atteint pendant la réunion) :
```
Décisions prises:
- [Sujet 1 : la décision prise, brièvement]
- [Sujet 2 : la décision prise, brièvement]
```

**Cas 3 - Pas d'arbitrage** : Supprimer complètement cette section si aucun arbitrage ne s'est dégagé.

#### 5. Actions
Format strict : - [Porteur] action
```
Actions:
- [Porteur] Libellé clair de l'action (deadline)
- [Porteur] Libellé clair de l'action (deadline)
- [Porteur] Libellé clair de l'action (deadline)
```
Exemples :
```
- [Seb] Coordonner intégration API avec Witko/CardiWeb (avant 15/04)
- [DAC] Arbitrer arrêts maladies en interne (avant 15/04)
- [Anne/Cécile] Finaliser participants atelier restauration (26/03 16h30)
- [Tous] Documenter journée type agent pour arbitrage 15/04
```

#### 6. Prochaines étapes
Prochaines réunions, jalons, ou étapes à venir :
```
Prochaines étapes:
- [Étape 1 : description et date]
- [Étape 2 : description et date]
```

#### 7. Signature
```
— [Prénom]
```

## Directives de rédaction

- **Ton** : Professionnel, direct, sans jargon inutile
- **Longueur** : 1 page max (3-5 min de lecture)
- **Aucun emoji** : Pas de symboles graphiques
- **Structure bullet** : Tous les points en listes à puces, pas de paragraphes
- **Verbosité des bullets** : Chaque bullet 2-3 lignes minimum, pas une seule phrase courte
- **Participants** : Liste avec rôle/contexte entre parenthèses
- **Points clés** : Décrire le contexte/enjeu, pas juste une décision nue
- **Arbitrages** : Séparer les questions ouvertes qui demandent une décision
- **Actions** : Format STRICT - [Porteur] action (deadline)
- **Prochaines étapes** : Dates et contexte clairs

## Points de contrôle

- Pas de paragraphes (que des bullets)
- Actions clairement assignées et datées
- Format [Porteur] action respecté
- Tone professionnel et scannable
- Pas de détails secondaires sauf s'ils bloquent quelqu'un
- Aucun emoji ou symbole graphique
